# Phase 6B.2 physical navigation

**Live Sensors · Step Navigation** estimates the astronaut's Mars position from foreground native steps and calibrated device attitude. **Demo Movement** remains the separately selected simulated route animation. Earth location is available to the opt-in Movement Log and Sensor Test. Earth fixes apply zero Mars meters, regardless of permission, precision, speed, or course.

## Short walking check

1. Open **Jezero Crater** with the assigned astronaut. Open **Astronaut → Device Sensors** and select **Live Sensors · Step Navigation**. Allow Motion & Fitness on the iPhone or Physical Activity on Android when prompted.
2. Close the Astronaut sheet. Select a waypoint or tap an in-bounds point and press **Start Navigation**. Note the starting distance in the mission header.
3. In **Astronaut**, choose **Calibrate Walking Direction**. Tilt the screen up and point the phone's top edge in the direction you intend to walk. Confirm to align that physical direction with the selected destination's current Mars bearing. Keep the phone aligned with your path. Calibrate again if you change how you hold it.
4. Stand still for 10 seconds, walk 10–20 real steps, then stop. Check **Total steps**, **Estimated distance traveled**, and **Sensor source** in Astronaut. **Movement Log** also shows the number of steps applied to the pose. Compare remaining distance in the mission header before and after the walk. Leave the app in the foreground and allow time for a pending native batch to arrive. Wait 10 seconds after stopping before pausing. After the batch settles, the distance should hold steady. The app's readouts are sufficient for this check.

## How displacement is estimated

- **iPhone 16 / ARES-01** uses foreground `CMPedometer` cumulative readings from the start of each collection window. Dart subtracts the previous cumulative value once per increasing timestamp. A batch can contain multiple steps. Same-window native distance can replace the stride estimate when the delta is plausible. If live delivery lags, the bridge queries the same active foreground window and accepts only an increase over the shared cumulative total. The separate, opt-in capture query stays in the local diagnostics.
- **OPPO CPH2579 / ARES-02** registers the step counter and step detector with zero report latency requested, subject to Physical Activity permission. The counter's initial total establishes a baseline, including when its timestamp predates listener registration. The detector buffers unmatched timestamps for up to three seconds. A timely counter delta covers overlapping detector events. If the counter stalls or its late initial baseline misses detector events, the detector supplies the rest of that foreground window. If neither hardware sensor supplies an increment, the existing rhythm detector can use linear acceleration, gravity, and gyroscope readings. It requires repeated, plausibly spaced peaks in the vertical signal and rejects isolated, horizontal, or abrupt handling motion. After a five-second hardware grace period it becomes the sole source for that window. The readout labels these steps as estimated. Repeated vertical hand motion can resemble walking, and the fallback can miss unusually slow or irregular steps.
- **Stride length** defaults to 0.70 m per step. Use **Set Stride Length** to enter a personal estimate from a measured distance divided by counted steps. Calibration stays on the device and is stored separately for each astronaut. If native distance is available for the same interval and falls within 0.25–1.50 m per step, it replaces the stride estimate for those steps.
- **Direction** uses relative changes from the explicit calibration with Core Motion device attitude on iOS and the game rotation vector or rotation vector on Android. The last valid heading near a step interval's endpoint represents a batch that has no individual step timestamps. The app keeps up to 45 seconds of heading history and accepts headings up to two seconds before the interval endpoint. If the batch crosses the calibration boundary or lacks a reliable heading, it can increase the detected count without moving the estimated pose. Pausing, backgrounding, an interface orientation change, or a sustained loss of attitude requires recalibration.
- **Mars position** comes from projecting each accepted displacement onto the Mars 2000 sphere. The mission radius limits destination selection. The position can move beyond the radius when the astronaut walks away. The route and readouts reflect the estimated position. Return to Base becomes available beyond 100 Mars meters. Arrival within 8 meters of the target ends guidance and announces arrival once while keeping the estimated position.

Firebase keeps the existing mission session and astronaut IDs. It publishes the Mars pose, heading, movement mode, and quality through the existing presence writer. GPS, native step data, and stride settings stay on device. Jezero uses `missions/jezero/sessions/field-test-01`.
